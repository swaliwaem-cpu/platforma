# План реализации закрытой платформы недвижимости

## Правило ведения плана

- Каждый пункт выполнения отмечается чекбоксом.
- Невыполненный пункт: `[ ]`.
- Выполненный пункт: `[x]`.
- По мере выполнения проекта нужно обновлять этот файл и менять `[ ]` на `[x]`.
- Перед крупными изменениями нужно кратко подтвердить следующий блок работ с пользователем.

## Summary

Файл: `plan.md`.

Формат выполнения: каждый пункт отмечается чекбоксом `[ ]`; после выполнения меняется на `[x]`.

Стратегия:

- начинать с аудита WordPress-базы;
- использовать `React + Vite`, `NestJS`, `PostgreSQL + PostGIS`, `Prisma`, `Redis + BullMQ`;
- для файлов на старте использовать `Local + MinIO`;
- не добавлять зависимости вне утверждённого стека без отдельного согласования;
- после создания `plan.md` остановиться и спросить пользователя, можно ли стартовать выполнение.

## Key Changes / Public Interfaces

- Monorepo: `apps/web`, `apps/api`, `packages/shared`, `tools/wp-import`.
- API: `/auth`, `/objects`, `/developers`, `/locations`, `/metro`, `/map`, `/users`, `/files`, `/wordpress-import`, `/audit-log`.
- Frontend routes: `/login`, `/catalog`, `/catalog/map`, `/objects/:slug`, `/cabinet`, `/admin/*`.
- Prisma entities: `User`, `Role`, `Permission`, `RealEstateObject`, `Developer`, `Location`, `MetroStation`, `File`, `ObjectImage`, `ObjectFile`, `AuditLog`, `ImportReport`.
- Env files: `.env.example` для root, `apps/api`, `apps/web`, `tools/wp-import`.
- Scripts: `dev:web`, `dev:api`, `db:migrate`, `db:seed`, `wp-import:preview`, `wp-import:run`.

## Assumptions

- На первом этапе не реализуются SEO, sitemap, OpenGraph, 301 redirects, CRM, обучение, курсы, тесты, платежи и сложная аналитика.
- Storage по умолчанию: `MinIO` локально как S3-compatible слой.
- Практический порядок: сначала WordPress audit, затем каркас проекта.
- Чекбоксы должны обновляться прямо в `plan.md` по мере выполнения.
- Любые новые зависимости сверх утверждённого стека добавляются только после отдельного согласования.
