# Подтверждённые бизнес-правила

Этот документ содержит только подтверждённые продуктовые правила Training V2.

## Пользователи и доступ

- Используются существующие пользователи Platforma.
- Отдельная таблица сотрудников и отдельная регистрация Training не нужны.
- Используются существующие `Role` и `Permission`.
- Администратор глобально открывает и закрывает проекты.
- У всех eligible-сотрудников одинаковый список открытых проектов.
- Индивидуальных назначений проектов в первой версии нет.
- Порядок проектов задаёт администратор.
- Проект может опционально ссылаться на существующий `RealEstateObject`.

## Проект и экзамен

- У проекта ровно один главный вопрос.
- У проекта ровно десять дополнительных вопросов.
- Экзамен состоит из одного главного и трёх дополнительных вопросов.
- Три дополнительных вопроса выбираются случайно.
- Внутри одной попытки дополнительные вопросы не повторяются.
- Между разными попытками вопросы могут повторяться.
- Выбор дополнительных вопросов не зависит от качества главного ответа.

## Формат ответа

- В конечном продукте ответы принимаются voice-сообщениями.
- Один ответ может состоять из нескольких voice-сегментов.
- Ответ завершается отдельным действием «Завершить ответ».

## Попытки и время

- Попытка расходуется после явного подтверждения старта.
- Брошенная начатая попытка считается использованной.
- Отменить или продолжить попытку позднее нельзя.
- Лимит попыток настраивается для каждого проекта.
- Лимит попыток по умолчанию равен трём.
- Возможность пересдачи после успешного результата настраивается для проекта.
- Один общий таймер действует на всю попытку.
- Значение таймера настраивается для проекта.
- В будущей voice-реализации при окончании времени разрешается закончить уже
  начатый voice-сегмент.
- После завершения этого сегмента попытка завершается.

## Оценивание

- Общая шкала — 100 баллов.
- Главный ответ даёт максимум 55 баллов.
- Каждый из трёх дополнительных ответов даёт максимум 15 баллов.
- Итоговая формула: `55 + 15 + 15 + 15 = 100`.
- Подтверждённая distinct фактическая ошибка даёт штраф `−5`.
- Одна ошибка не штрафуется дважды.
- Утверждение сверх загруженных материалов автоматически не штрафуется.
- В будущем такое утверждение требует ручной проверки.
- Проходной балл настраивается для проекта.
- Проходной балл по умолчанию равен 75.
- Основной результат проекта — лучший финальный подтверждённый балл.
- После административного пересмотра используется финальный подтверждённый балл.
- Точная внутренняя разбивка 55 и 15 по отдельным критериям не утверждена.
- Неутверждённые веса критериев нельзя считать продуктовым правилом.

## Видимость для сотрудника

Сотрудник видит:

- доступные проекты и статус проекта;
- число использованных и оставшихся попыток;
- лучший и последний подтверждённые результаты;
- статус «Пройдено», «Не пройдено» или «Требует проверки»;
- безопасную итоговую разбивку по критериям, если она существует и согласована
  с финальным баллом.

Сотрудник не видит:

- чужие результаты и общий рейтинг;
- полный transcript;
- конкретные фактические ошибки;
- утверждения сверх материалов;
- внутренние комментарии проверки;
- аудиозаписи;
- скрытые эталонные факты и ответы.

## Видимость для администратора

В будущих этапах администратор должен иметь возможность видеть:

- результаты сотрудников и историю попыток;
- вопросы, ответы и transcript;
- фактические ошибки и утверждения сверх материалов;
- аудио, breakdown и review;
- рейтинг.

Полный административный results/review/ranking UI не относится к первому этапу.

## Материалы

В конечной версии поддерживаются:

- ручной текст;
- PDF;
- DOCX;
- PPTX;
- XLSX.

На первом этапе используются только ручной ввод проекта и вопросов. Загрузка и
разбор документов, автоматические факты и форматы PDF/DOCX/PPTX/XLSX в него не
входят.
