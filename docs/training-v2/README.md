# Training V2

## Назначение

Training V2 — новый учебно-экзаменационный модуль внутри Platforma.
Он проектируется независимо от прежних Training-реализаций и развивается
короткими вертикальными этапами с отдельной приёмкой каждого этапа.

Этот каталог — канонический комплект проектных документов Training V2.
Он не является разрешением на реализацию.

## Источники истины

Приоритет требований:

1. Текущая явно утверждённая задача пользователя.
2. [BUSINESS_RULES.md](BUSINESS_RULES.md) — подтверждённые продуктовые правила.
3. [DECISIONS.md](DECISIONS.md) — активные технические решения и открытые вопросы.
4. [ARCHITECTURE.md](ARCHITECTURE.md) — минимальная архитектура Stage 1.
5. [CURRENT_STAGE.md](CURRENT_STAGE.md) — единственный текущий этап.
6. [ACCEPTANCE.md](ACCEPTANCE.md) — критерии его завершения.
7. Текущие `AGENTS.md`, код, Prisma schema, package scripts, тесты и активные
   общие руководства Platforma в пределах конкретной работы.

При расхождении более поздний пункт не отменяет более ранний.

## Порядок чтения

После этого файла читать документы в таком порядке:

1. [BUSINESS_RULES.md](BUSINESS_RULES.md).
2. [DECISIONS.md](DECISIONS.md).
3. [ARCHITECTURE.md](ARCHITECTURE.md).
4. [CURRENT_STAGE.md](CURRENT_STAGE.md).
5. [ACCEPTANCE.md](ACCEPTANCE.md).

`CURRENT_STAGE.md` описывает только активный этап и в будущем перезаписывается,
а не превращается в журнал.

## Вертикальный принцип

- Каждый этап должен давать один проходимый пользовательский сценарий.
- Инфраструктура следующего этапа заранее не создаётся.
- Переход возможен только после автоматических проверок, ручного сценария
  текущего этапа и отдельного разрешения пользователя.
- До отдельного разрешения после проектирования production-код не создаётся.

## Правило конфликтов

Если задача, бизнес-правила, активное решение и текущий код противоречат друг
другу, работа останавливается. Противоречие показывается пользователю явно;
новое поведение не выбирается молча.

## Изоляция от прежнего Training

Запрещено использовать как источник требований или кода:

- старые ветки и Git history;
- удалённые или архивные Training-документы;
- старые prompts, планы, отчёты и журналы;
- прежний Training-код и migrations;
- remote branches и код из других веток.

В текущем checkout найдены неканонические артефакты
`apps/api/apps/api/prisma/migrations/20260725210000_add_training_module/`
и `docs/training/.DS_Store`. Их содержимое не используется. Они не относятся к
Training V2 и не удаляются без отдельного разрешения.

## Что не является требованием

- Возможности будущих этапов, пока они не вошли в `CURRENT_STAGE.md`.
- Исторические решения и поведение прежнего Training.
- TODO, комментарии, generated output и случайные файлы вне этого каталога.
- Пример механизма, если он не закреплён в `DECISIONS.md`.
- Зелёный mock или static test без требуемой runtime/PostgreSQL-проверки.
