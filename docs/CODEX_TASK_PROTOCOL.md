# Codex Task Protocol

Постоянный рабочий протокол Codex для задач в этом проекте. Он не заменяет `AGENTS.md` и `rules/*`, а задает порядок чтения, подготовки, изменений и финального отчета.

## Перед любой задачей

- Прочитать `AGENTS.md`.
- Прочитать `rules/*`.
- Прочитать `docs/PROJECT_INDEX.md`.
- Прочитать `docs/FEATURE_MAP.md`.
- Прочитать `docs/RISK_ZONES.md`.
- Прочитать `docs/CODEX_LOG.md`.
- Если задача frontend/UI - прочитать `docs/PAGES_AND_ROUTES.md`, `docs/STATE_AND_LOGIC.md`, `docs/PRODUCT_AND_UI_CONTEXT.md`.
- Если задача backend/API/data - прочитать `docs/API_AND_DATA.md`, `docs/STATE_AND_LOGIC.md`.
- Если задача import/feed/repair - прочитать `docs/IMPORT_INDEX.md`, `docs/API_AND_DATA.md`, `docs/RISK_ZONES.md`.

## Перед изменениями

- Найти связанные файлы.
- Найти все использования файлов, которые планируется менять.
- Определить risk zones в `docs/RISK_ZONES.md`.
- Составить короткий план.
- Если изменение затрагивает больше 3 файлов - дождаться подтверждения плана.

## Во время работы

- Менять минимальное количество файлов.
- Не делать попутный рефакторинг.
- Не добавлять зависимости без разрешения.
- Не менять публичные API/shared contracts без объяснения.
- Не менять Prisma schema/migrations без отдельного понимания последствий.
- Не трогать несвязанные файлы.
- Не менять UI layout или порядок блоков без согласования.

## После изменений

- Запустить релевантные проверки из `rules/commands.md` и docs по зоне задачи.
- Обновить `docs/CODEX_LOG.md`.
- В финальном ответе указать:
  - что сделано;
  - какие файлы изменены;
  - какие проверки запущены;
  - какие риски;
  - что проверить вручную.
