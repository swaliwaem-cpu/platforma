# T01: Авторизованный ИИ-помощник и оболочка разговора

**What to build:** дать авторизованному пользователю Platforma рабочий плавающий чат на всех внутренних страницах: разговор сохраняется, безопасно переживает переходы, показывает понятный прогресс и отвечает через fake provider, не выполняя никаких внешних действий.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Плавающая кнопка помощника присутствует во всём authenticated app shell и отсутствует до успешной авторизации.
- [ ] Backend проверяет существующую авторизацию, право чтения объектов и server-side feature state; сокрытие кнопки на frontend не считается защитой.
- [ ] Пользователь может создать разговор, отправить сообщение и получить persisted assistant run с финальным ответом от deterministic fake provider.
- [ ] Conversation, messages и runs имеют самостоятельный lifecycle; пользователь читает только собственные разговоры, а UUID probing не раскрывает чужие данные.
- [ ] Повтор одного idempotency key не создаёт второе пользовательское сообщение или второй model run.
- [ ] Клиент показывает только безопасные этапы «понимаю запрос», «ищу данные», «сравниваю варианты» и «формирую ответ», не раскрывая chain of thought.
- [ ] Временная ошибка допускает retry того же запуска без дубликатов; stale responses, unmount и повторные отправки обработаны явно.
- [ ] Desktop-чат перетаскивается и масштабируется, сохраняет geometry и имеет только действие сброса; pin и другие лишние controls отсутствуют.
- [ ] Mobile-чат открывается как полноэкранная sheet и остаётся пригодным для touch-взаимодействия.
- [ ] Открытый разговор сохраняется при переходе между страницами Platforma; пользователь может открыть собственную историю за последние 30 дней.
- [ ] Текущий ЖК, лот, застройщик или фильтры каталога передаются как видимый removable context chip, который можно убрать до отправки.
- [ ] Chat surface имеет loading, empty, error и retry states, доступные labels и focus states, keyboard navigation, подходящие touch targets и reduced-motion поведение.
- [ ] MVP только ищет и отвечает: он не создаёт лиды, CRM-записи, бронирования, задачи, сообщения или новые PDF.
- [ ] Shared user-facing contracts не содержат Prisma entities, secrets, provider payloads, evidence internals или authorization details.
- [ ] Targeted API и web tests доказывают 401/403, ownership, idempotency, progress contract, route continuity, desktop/mobile shell и отсутствие реальных provider calls.
