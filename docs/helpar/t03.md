# T03: Официальные источники, ingestion и гибридная база знаний

**What to build:** провести один полный путь от публичной официальной страницы до ответа помощника, затем расширить его до управляемого пилота: источники версионируются, факты ищутся гибридно, а отсутствующий в Platforma лот или актуальная акция появляются в ответе с правильным приоритетом и ссылкой.

**Blocked by:** T02 — Поиск, сравнение и grounded-ответы по данным Platforma.

**Status:** ready-for-agent

- [ ] Knowledge Source Registry является единственным реестром canonical URL, типа, приоритета, расписания, состояния и connector configuration.
- [ ] Управление источниками и ручной refresh защищены отдельным additive permission, не привязанным к названию роли.
- [ ] Реализован end-to-end connector хотя бы для одной официальной страницы ЖК: register, fetch, immutable revision, extraction, retrieval и подтверждённый ответ помощника.
- [ ] Пилот масштабируется до 20 ЖК от 5–7 выбранных застройщиков и релевантных официальных developer/bank promotion pages.
- [ ] Production parsers CIAN, Домклик, Яндекс Недвижимость и Новострой-М не реализуются; для них существуют только выключенные connector entry points с общим контрактом.
- [ ] Connector извлекает только публичные HTML, DOM и JSON-LD данные; screenshots, OCR, CAPTCHA bypass, authorization bypass и непубличные данные не используются.
- [ ] Fetch защищён registry allowlist, проверкой protocol и DNS/IP, redirect limits, timeouts, content-type validation и maximum response size.
- [ ] Source worker поддерживает ручной refresh и запуск не реже раза в 24 часа, bounded retries, идемпотентность, restart recovery и безопасную классификацию ошибок.
- [ ] Raw HTML/JSON сохраняются сжато и неизменно как Source Revision с checksum, HTTP metadata, fetchedAt, processing status и ссылкой на предыдущую revision.
- [ ] Неизменившийся checksum не запускает повторные extraction и embeddings.
- [ ] Normalized facts и searchable chunks сохраняют provenance до конкретной Source Revision и достаточные timestamps для определения freshness.
- [ ] Гибридный retrieval объединяет structured SQL, PostgreSQL full-text search и pgvector semantic search; модель не получает весь corpus целиком.
- [ ] Embeddings рассчитываются пакетно только для изменившихся chunks; модель embeddings выбирается по воспроизводимому benchmark перед rollout.
- [ ] Динамический retrieval cache живёт не более шести часов и инвалидируется новой source revision; финальный пользовательский ответ долгосрочно не кешируется.
- [ ] Platforma остаётся primary источником цены и наличия; официальный сайт застройщика используется только при отсутствии соответствующих внутренних данных.
- [ ] Официальная страница ЖК является canonical источником описания, архитектуры, инфраструктуры и других статических характеристик.
- [ ] Ипотека, рассрочка, скидки и бонусы получают приоритет официальных страниц застройщика или банка; конфликт разрешается детерминированной таблицей, а не предпочтением модели.
- [ ] Если подходящего лота нет в Platforma, но он найден на официальном сайте застройщика, ответ содержит прямую внешнюю ссылку и freshness.
- [ ] Source health показывает последнюю успешную индексацию, ошибки и состояние каждого источника; оператор может адресно обновить один источник или ЖК.
- [ ] Evidence прикрепляется из retrieval results без отдельного модельного запроса и не увеличивает число генераций.
- [ ] Source revisions сохраняются бессрочно; статические facts остаются активными до появления новой canonical revision.
- [ ] Connector tests используют local stub HTTP server и fixtures и покрывают redirects, timeout, retry classification, oversized/unsupported content, SSRF, checksum no-op, revision chain и safe failure без реальных внешних вызовов.
