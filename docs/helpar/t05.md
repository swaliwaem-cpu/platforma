# T05: Геопоиск по ручной точке и названию места

**What to build:** дать пользователю единый геопоиск внутри чата: выбрать точку вручную либо написать название места, задать точный радиус и получить ранжированные предложения с расстояниями без зависимости property search от карты или геокодера.

**Blocked by:** T02 — Поиск, сравнение и grounded-ответы по данным Platforma; T03 — Официальные источники, ingestion и гибридная база знаний; T04 — Полная миграция карт с Yandex Maps на MapLibre.

**Status:** ready-for-agent

- [ ] Additive migration создаёт database-derived nullable geography Point SRID 4326 из существующих latitude/longitude и GiST index, не меняя canonical coordinate fields.
- [ ] Geography существует только при полной валидной паре координат; существующие объекты backfill-ятся без изменения latitude/longitude, а старые migrations не редактируются.
- [ ] Radius Search принимает validated anchor, положительный radius в configured bounds и существующие object/lot filters и выполняется server-side индексированным PostGIS predicate.
- [ ] Ответ возвращает explicit serialized anchor, radiusMeters, meter-correct GeoJSON polygon, result markers и distanceMeters без Prisma/geography internals.
- [ ] FeedUnit участвует в геопоиске через связанный RealEstateObject и не получает отдельные coordinates.
- [ ] Point picker открывается внутри chat surface: на desktop занимает большую часть resizable окна, на mobile — full-screen sheet.
- [ ] Пользователь двигает карту под неподвижным crosshair, выбирает 1, 2, 3 или 5 км либо сохраняет другой допустимый текстовый радиус.
- [ ] Pan до confirm не запускает property search; confirm запускает один run, cancel не меняет контекст.
- [ ] После подтверждения отображается editable/removable geo chip с точкой и радиусом.
- [ ] LocationIQ реализован только как backend Geo Provider; browser не получает API key и не вызывает provider напрямую.
- [ ] Place Resolver проверяет confirmed local alias, затем bounded LocationIQ query, затем официальный адрес из Knowledge Base, ambiguous candidates и manual-point fallback.
- [ ] Если пользователь явно указал другой город, resolver меняет search context и не ограничивает запрос Москвой молча.
- [ ] При неоднозначности показывается максимум три normalized candidates; при нулевом результате доступны «Указать на карте» и «Уточнить название».
- [ ] Confirmed aliases хранятся отдельно от provider cache и управляются пользователем с соответствующим административным permission.
- [ ] Geo cache key учитывает normalized query, locale, country и viewbox и соблюдает retention активного provider plan.
- [ ] Geo Provider защищён timeout, bounded retry, RPS limit, daily budget и circuit breaker; telemetry не содержит credentials или raw secret payload.
- [ ] Результат содержит максимум три primary и максимум две alternative markers, визуально различает их и показывает расстояние до anchor.
- [ ] Радиус является hard filter и расстоянием по прямой; routing, walking/driving distance и travel time не подмешиваются.
- [ ] Перемещение подтверждённого anchor запускает только новый PostGIS search и не вызывает LocationIQ.
- [ ] Отказ tiles оставляет рабочие textual result cards; отказ geocoder переводит к ручной точке; ошибка property API показывается отдельно.
- [ ] Map views, manual point и известные coordinates не расходуют LocationIQ credits.
- [ ] Disposable PostGIS tests покрывают backfill, null coordinates, inside/boundary/outside radius, distance ordering, combined lot filters и использование GiST на representative dataset.
- [ ] Fake Geo Provider и browser tests покрывают aliases, ambiguity, timeout, 4xx/5xx/429, budgets, circuit breaker, picker confirm/cancel, primary/alternative markers и degraded modes без реальных provider calls.
