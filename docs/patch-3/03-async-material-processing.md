# 03. Асинхронное создание материалов и вопросов

Статус: предложение к реализации<br>
Приоритет: P1<br>
Область: PDF, URL, Platforma object import, генерация вопросов

## Проблема

Создание источника выполняет загрузку, извлечение текста и OpenAI-генерацию внутри одного HTTP-запроса. PDF допускается до 100 МБ и доступен сервису как `Buffer`. Импорт объекта может последовательно обработать несколько PDF, после чего ждать генерацию вопросов. Это повышает риск HTTP timeout, повторных кликов, скачков памяти и неясного результата для администратора.

Затрагиваемые участки:

- `training-material.controller.ts`;
- `training-material.service.ts`;
- `training-material-extraction.ts`;
- `training-project-knowledge.service.ts`;
- `TrainingMaterialsPanel.tsx`;
- Prisma schema и additive migration.

## Целевое решение

HTTP endpoint должен быстро валидировать запрос, фиксировать операцию и возвращать `202 Accepted` с `operationId`. Дальнейшая обработка выполняется training-specific background worker.

Предлагаемые состояния:

- `QUEUED`;
- `STORING`;
- `EXTRACTING`;
- `GENERATING`;
- `PERSISTING`;
- `READY`;
- `FAILED` или `CANCELLED`.

Для операции следует сохранять прогресс по файлам, безопасный error code, source hash и knowledge version. Повторный запрос с тем же idempotency key должен возвращать существующую операцию.

## Работа с файлами

- Не держать 100 МБ целиком в heap дольше необходимого.
- Сначала потоково сохранить файл в private storage и вычислить checksum.
- Извлекать один PDF за раз с ограничением общей concurrency.
- Удалять временные файлы в `finally`.
- При ошибке сохранять FAILED revision только в соответствии с текущим продуктовым контрактом.

## UI

Администратор должен видеть текущий этап, количество обработанных PDF, безопасную ошибку и возможность повторить только неуспешную операцию. Перезагрузка страницы не должна терять прогресс.

## Границы

- Не добавлять внешнюю очередь или новую библиотеку без необходимости.
- Не менять правила provenance и immutable revisions.
- Не создавать вопросы частично: применение 1 MAIN + 10 FOLLOW_UP остаётся атомарным.

## Критерии приёмки

- HTTP-запрос не ждёт OpenAI.
- Двойной клик не создаёт две платные генерации.
- Restart worker продолжает операцию с последнего безопасного этапа.
- Большой PDF не вызывает неконтролируемый рост heap.
- Ошибка одного PDF при object import отображается отдельно и не скрывает остальные результаты.
- Stale knowledge version не перезаписывает более новую редакцию проекта.
