Развертывание Platforma на Beget

Пошаговая инструкция по загрузке проекта на VPS/VDS Beget, настройке Docker, PostgreSQL/PostGIS, Redis, S3/MinIO, Nginx, SSL и первичной проверке платформы.

Проект: /Users/nick/Documents/platforma. Обновлено: 26 июля 2026.

Важно. Этот проект нельзя просто загрузить в public_html обычного shared-хостинга. Ему нужен постоянно работающий NestJS API, PostgreSQL с расширением PostGIS, Redis, S3-совместимое хранилище и сборка через pnpm. Рабочий вариант для Beget - VPS/VDS в Beget Cloud с Docker.

0. Что есть в проекте

  • apps/web - Vite + React + Tailwind frontend.
  • apps/api - NestJS API, Prisma, auth/RBAC, объекты, файлы, карта, WordPress import.
  • packages/shared - общие TypeScript-типы.
  • tools/wp-import - CLI-инструмент импорта данных из WordPress.
  • docker-compose.yml - базовая development-конфигурация PostgreSQL/PostGIS, Redis, MinIO, API и web.
  • docker-compose.production.yml - обязательный production override для API и Telegram transport.

1. Подготовьте Beget VPS

  1. В панели Beget создайте VPS/VDS, а не обычный виртуальный хостинг.
  2. В маркетплейсе выберите образ Docker. Он устанавливает Ubuntu, Docker CE и Docker Compose.
  3. Рекомендуемая минимальная конфигурация: 2 CPU, 4 GB RAM, 40 GB NVMe. Для тяжелого импорта WordPress лучше больше.
  4. Создайте DNS-записи:
    • platform.example.ru A-record на IP сервера.
    • api.platform.example.ru A-record на IP сервера.
В примерах ниже замените SERVER_IP, platform.example.ru, api.platform.example.ru, пароли и секреты на свои значения.

2. Подключитесь к серверу

ssh root@SERVER_IP

Проверьте, что Docker работает:

docker run hello-world
docker compose version

3. Загрузите проект на сервер

Вариант A: через Git

mkdir -p /opt
cd /opt
git clone YOUR_REPOSITORY_URL platforma
cd /opt/platforma

Вариант B: через rsync с локальной машины

rsync -av --exclude node_modules --exclude dist --exclude .git \
  /Users/nick/Documents/platforma/ root@SERVER_IP:/opt/platforma/

После загрузки на сервере:

cd /opt/platforma

4. Создайте обязательный production env

cd /opt/platforma
cp .env.production.example .env.production
chmod 600 .env.production
nano .env.production

Замените все REPLACE_WITH_* и your-domain.ru. Значения из development .env.example для production не подходят. Минимальный Telegram-блок: 

COMPOSE_PROJECT_NAME=platforma

POSTGRES_DB=platforma
POSTGRES_USER=platforma
POSTGRES_PASSWORD=STRONG_POSTGRES_PASSWORD
DATABASE_URL=postgresql://platforma:STRONG_POSTGRES_PASSWORD@postgres:5432/platforma?schema=public

REDIS_URL=redis://redis:6379

MINIO_ROOT_USER=platforma_admin
MINIO_ROOT_PASSWORD=STRONG_MINIO_PASSWORD
MINIO_BUCKET=platforma
S3_ENDPOINT=http://minio:9000
S3_PUBLIC_ENDPOINT=http://minio:9000
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=platforma_admin
S3_SECRET_ACCESS_KEY=STRONG_MINIO_PASSWORD

API_PORT=3000
WEB_PORT=5173
VITE_API_URL=https://api.platform.example.ru
WEB_ORIGIN=https://platform.example.ru
PUBLIC_APP_URL=https://platform.example.ru

TRAINING_MODULE_ENABLED=true
TELEGRAM_BOT_TOKEN=REAL_BOT_TOKEN_FROM_BOTFATHER
TELEGRAM_BOT_USERNAME=real_bot_username
TELEGRAM_WEBHOOK_SECRET=GENERATE_LONG_RANDOM_SECRET
TELEGRAM_WEBHOOK_URL=https://api.platform.example.ru/training/telegram/webhook

JWT_ACCESS_SECRET=GENERATE_LONG_RANDOM_SECRET
JWT_REFRESH_SECRET=GENERATE_ANOTHER_LONG_RANDOM_SECRET
JWT_ACCESS_TTL=15m
JWT_REFRESH_TTL_DAYS=30
REFRESH_COOKIE_NAME=platforma_refresh_token

VITE_YANDEX_MAPS_API_KEY=

Секреты можно сгенерировать командой:

openssl rand -hex 32
Не оставляйте значения change-me-access-secret, change-me-refresh-secret, REPLACE_WITH_*, your-domain.ru и простые пароли из примера. Не публикуйте файл .env.production в репозиторий.

5. Используйте production Compose override

Не копируйте и не редактируйте development Compose вручную. Production всегда запускается двумя tracked-файлами: docker-compose.yml и docker-compose.production.yml. Override жёстко задаёт NODE_ENV=production и TELEGRAM_TRANSPORT_MODE=real.

Через required-variable syntax обязательны:

  • TELEGRAM_BOT_TOKEN;
  • TELEGRAM_BOT_USERNAME;
  • TELEGRAM_WEBHOOK_SECRET;
  • TELEGRAM_WEBHOOK_URL;
  • PUBLIC_APP_URL.
TELEGRAM_WEBHOOK_URL и PUBLIC_APP_URL должны использовать HTTPS и реальные production hostnames. localhost, 127.0.0.1, example/test/fake placeholders и development username запрещены runtime validation. Закройте PostgreSQL, Redis и MinIO внешним firewall/security group: базовый Compose публикует их порты для локальной разработки.

6. Проверьте конфигурацию и запустите проект

Сначала выполните только render/validation без запуска контейнеров:

cd /opt/platforma
docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  config >/dev/null

Команда обязана завершиться ошибкой, если отсутствует любая обязательная Telegram-переменная. После успешной проверки выполните production запуск: 

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  up -d --build

Проверьте контейнеры и зафиксированный real transport без вывода секретов:

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  ps

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  exec api sh -c \
  'test "$NODE_ENV" = production && test "$TELEGRAM_TRANSPORT_MODE" = real'

API-контейнер при старте выполнит Prisma migrations через команду из apps/api/Dockerfile.

Проверьте здоровье API:

curl http://127.0.0.1:3000/health

Ожидаемый ответ:

{
  "status": "ok",
  "database": "ok",
  "postgis": true
}

7. Создайте первого admin-пользователя

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  exec \
  -e ADMIN_EMAIL=admin@example.ru \
  -e ADMIN_NAME="Platform Admin" \
  -e ADMIN_PASSWORD="STRONG_ADMIN_PASSWORD" \
  api pnpm --filter @platforma/api db:seed
После первого входа замените пароль администратора. Значения ADMIN_PASSWORD нужны только для первичного seed.

8. Настройте Nginx и SSL

apt update
apt install -y nginx certbot python3-certbot-nginx

Создайте конфиг для frontend:

nano /etc/nginx/sites-available/platforma-web
server {
  server_name platform.example.ru;

  location / {
    proxy_pass http://127.0.0.1:5173;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}

Создайте конфиг для API:

nano /etc/nginx/sites-available/platforma-api
server {
  server_name api.platform.example.ru;

  client_max_body_size 200m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}

Включите сайты и выпустите SSL:

ln -s /etc/nginx/sites-available/platforma-web /etc/nginx/sites-enabled/platforma-web
ln -s /etc/nginx/sites-available/platforma-api /etc/nginx/sites-enabled/platforma-api
nginx -t
systemctl reload nginx
certbot --nginx -d platform.example.ru -d api.platform.example.ru

9. Если используете Beget S3 вместо MinIO

  1. В панели Beget создайте S3 bucket вручную.
  2. Скопируйте из панели: URL, имя bucket, Access key и Secret key.
  3. В .env.production замените S3-настройки:
S3_ENDPOINT=https://s3.ru1.storage.beget.cloud
S3_PUBLIC_ENDPOINT=https://s3.ru1.storage.beget.cloud
S3_REGION=ru1
S3_ACCESS_KEY_ID=ACCESS_KEY_FROM_BEGET
S3_SECRET_ACCESS_KEY=SECRET_KEY_FROM_BEGET
MINIO_BUCKET=YOUR_BEGET_BUCKET_NAME
Не указывайте в S3_PUBLIC_ENDPOINT URL уже с bucket. Код проекта сам добавляет MINIO_BUCKET к endpoint. Если вставить URL с bucket, ссылки могут получить дубль bucket.

Перезапустите API после изменения .env.production:

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  up -d --build api

10. WordPress import

Если нужен импорт из WordPress, заполните в .env.production:

WP_DB_HOST=
WP_DB_PORT=3306
WP_DB_USER=
WP_DB_PASSWORD=
WP_DB_NAME=
WP_TABLE_PREFIX=wp_
WP_POST_TYPE=nedvizhimosts
WP_IMPORT_LIMIT=
WP_UPLOADS_HOST_PATH=/absolute/path/to/wp-content/uploads
WP_UPLOADS_PATH=/wp-uploads

Сначала запускайте preview:

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  exec api pnpm wp-import:preview

Только после проверки отчета запускайте полный импорт:

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  exec api pnpm wp-import:run

13. Ручная проверка graceful shutdown

API использует TELEGRAM_WORKER_DRAIN_TIMEOUT_MS=10000, а Docker ждёт до 30s перед SIGKILL. Выполните во время контролируемого Telegram job: 

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  stop api

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  logs --tail=200 api

docker compose \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --env-file .env.production \
  exec postgres sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT kind, status, attempts, lock_owner, last_error_code FROM training_jobs ORDER BY updated_at DESC LIMIT 20;"'

Критерии:

  • Node получает SIGTERM как PID 1, а Nest вызывает lifecycle hooks.
  • После начала shutdown новые Telegram jobs не переходят в RUNNING.
  • Активный job успевает завершиться в пределах 10 секунд либо возвращается в PENDING с TELEGRAM_SHUTDOWN_RELEASE.
  • После остановки не остаётся Telegram job с lock остановленного worker.
  • Контейнер завершается до истечения Docker 30s grace period.

14. Финальный чеклист

  • VPS создан именно с Docker, а не обычный shared-хостинг.
  • DNS доменов platform.example.ru и api.platform.example.ru указывает на IP сервера.
  • Файл .env.production заполнен production-значениями и имеет mode 600.
  • NODE_ENV=production и TELEGRAM_TRANSPORT_MODE=real подтверждены внутри API.
  • Все пять обязательных Telegram/public URL переменных заданы без placeholder-значений.
  • Пароли PostgreSQL, MinIO/S3, admin и JWT secrets заменены на сильные.
  • PostgreSQL, Redis и MinIO не открыты напрямую в интернет.
  • Production Compose command с двумя файлами показывает запущенные сервисы.
  • /health возвращает database: "ok" и postgis: true.
  • SSL выпущен через Certbot для frontend и API доменов.
  • Вход под admin работает.
  • Открываются каталог, карта, карточка объекта, админка пользователей и объектов.
  • Загрузка изображений и PDF работает.
  • Если используется WordPress import, сначала проверен preview.

15. Спорные места и что улучшить позже

  • Текущий apps/web/Dockerfile запускает pnpm dev. Для настоящего production позже лучше заменить это на сборку pnpm build:web и отдачу статических файлов через Nginx.
  • Managed PostgreSQL Beget можно использовать только если подключено расширение PostGIS. Если расширение недоступно, оставляйте postgis/postgis в Docker.
  • Beget S3 bucket нужно создать вручную в панели, потому что создание bucket через SDK у Beget ограничено.
