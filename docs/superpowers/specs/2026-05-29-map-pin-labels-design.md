# Дизайн: подписи пинов на карте

## Цель

Заменить текущий маркер карты на два состояния:

- до `zoom 13` включительно показывать компактную точку;
- с `zoom >= 14` показывать пин с текстом.

Текст пина должен редактироваться в админском списке объектов через новую quick-edit колонку `Имя карты` и использоваться на карте без перехода в полную карточку объекта.

## Данные

В `RealEstateObject` добавляется nullable поле `mapName`, в базе `map_name`, с ограничением до 16 символов.

Поле прокидывается через:

- Prisma schema и миграцию;
- API объектов;
- API карты;
- shared-типы `RealEstateObjectBase` и `MapObject`;
- frontend quick-edit persistence.

Поле не добавляется в полную форму редактирования объекта.

## Админка

В quick-edit таблицу объектов добавляется последняя колонка `Имя карты`.

Поведение:

- редактор: обычный text input, как у других текстовых quick-edit колонок;
- сохранение: `PATCH /objects/:id` с payload `{ mapName: string | null }`;
- пустая строка сохраняется как `null`;
- значение длиннее 16 символов отклоняется на API;
- локальная строка таблицы обновляется из ответа API.

Горизонтальный скролл таблицы допустим.

## Маркеры Карты

Используются SVG-файлы:

- `Ресурс 4.svg` - точка для дальнего масштаба;
- `Ресурс 5.svg` - пин для приближенного масштаба.

Точка:

- примерно на 30% меньше текущего маркера `36px`, целевой размер около `25px`;
- черная обводка `1px`;
- показывается до `zoom 13` включительно.

Пин:

- показывается с `zoom >= 14`;
- нижняя центральная точка хвостика является якорем координаты;
- размер пина должен соответствовать SVG и не растягиваться под текст;
- текст должен оставаться внутри формы пина.

## Текст Пина

Основной текст: `mapName`.

Если `mapName` пустой, используется fallback:

1. взять `title` объекта;
2. убрать типовые префиксы и слова: `ЖК`, `Ж.К.`, `Дом`, `Клубный дом`, `Жилой комплекс`, `Квартал`, `Апарт-комплекс`, `Апартаменты`, `Резиденция`, `Клубная резиденция`;
3. нормализовать пробелы и кавычки;
4. взять первые 6 видимых символов результата;
5. если после очистки ничего не осталось, взять первые 6 символов исходного `title`.

Fallback вычисляется на frontend при формировании `YandexMapPoint`, чтобы API оставался источником сохраненного значения, а не смешивал сохраненные и производные данные.

## Тестирование

Покрыть:

- shared-типы и API сериализацию нового поля;
- API update: сохранение `mapName`, очистка в `null`, отклонение значений длиннее 16 символов;
- quick-edit колонку и PATCH payload;
- fallback-формирование текста пина;
- CSS/шаблон маркера: наличие дальнего и приближенного состояний, `zoom >= 14`.

Ручная проверка:

- открыть карту каталога;
- проверить точку на дальнем масштабе;
- приблизить до `zoom 14` и проверить пин;
- проверить якорь пина по нижней центральной точке хвостика;
- проверить несколько значений `Имя карты` разной длины и подобрать кегль, если текст визуально не помещается.

## Ограничения

- Новые зависимости не добавляются.
- Логика списка объектов рядом с картой, балуна и защищенная модель карты не меняются.
- Полная форма объекта не получает поле `Имя карты`.
