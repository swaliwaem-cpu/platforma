# Дизайн: рабочая зона PDF-презентаций лотов

## Цель

Переработать раздел `/presentations` так, чтобы у каждого пользователя была сохраненная рабочая зона `В работе` с плитками лотов. Лоты можно добавлять туда напрямую из карточки объекта и таблицы лотов без обязательного создания подборки.

Подборки остаются отдельной сущностью: они доступны во вкладке `Мои подборки`, выбираются через боковую колонку и показывают свои лоты такими же плитками.

## Контекст

Текущая реализация центрирована вокруг `LotPresentationCollection`:

- `/presentations` показывает боковую колонку подборок и список лотов выбранной подборки;
- `LotCollectionAction` на странице объекта открывает выбор или создание подборки;
- `POST /lot-presentations/documents` уже умеет генерировать PDF по явному списку `unitIds` без обязательного `collectionId`;
- комментариев у лотов пока нет.

Новый сценарий требует persistent-состояния для `В работе`, поэтому localStorage или временное frontend-состояние не подходят.

## Принятые решения

- `В работе` сохраняется на сервере отдельно для каждого пользователя.
- Один и тот же лот может быть в `В работе` и в нескольких подборках одновременно.
- Добавление лота в подборку не удаляет его из `В работе`.
- Комментарии контекстные: комментарий к лоту в `В работе` не связан с комментариями этого же лота в подборках.
- Комментарии не попадают в PDF.
- Максимальная длина комментария: 1000 символов, обычный текст без форматирования.
- Порядок лотов: по порядку добавления, без ручной сортировки и drag-and-drop.
- `Скачать все` во вкладке `В работе` генерирует один PDF по всем лотам в работе.
- Иконка скачивания на плитке генерирует PDF только по одному лоту.
- `Очистить всё` удаляет только лоты из `В работе`; подборки и история PDF не меняются.
- Новые зависимости не добавляются.

## Data Model

Добавить модель `LotPresentationWorkspaceItem`:

- `id` - UUID;
- `userId` - владелец рабочей зоны;
- `unitId` - лот;
- `sortOrder` - порядок добавления;
- `comment` - nullable text/comment до 1000 символов;
- `createdAt`;
- `updatedAt`.

Связи:

- `User.lotPresentationWorkspaceItems`;
- `FeedUnit.lotPresentationWorkspaceItems`.

Ограничения и индексы:

- unique `[userId, unitId]`, чтобы один лот не дублировался в `В работе`;
- index `[userId, sortOrder]`;
- index `[unitId]`;
- cascade delete от пользователя и лота.

Расширить `LotPresentationCollectionItem`:

- добавить nullable `comment`;
- комментарий относится только к этому item в конкретной подборке.

Потребуется Prisma migration и обновление shared-контрактов.

## API Design

Все endpoints остаются в `LotPresentationsController` под `JwtAuthGuard`, как текущие endpoints PDF-презентаций.

Новые endpoints для `В работе`:

- `GET /lot-presentations/workspace` - вернуть сохраненные лоты пользователя в порядке добавления;
- `POST /lot-presentations/workspace/items` body `{ unitId }` - добавить лот в `В работе`;
- `DELETE /lot-presentations/workspace/items/:unitId` - удалить один лот из `В работе`;
- `DELETE /lot-presentations/workspace/items` - очистить всю рабочую зону пользователя;
- `PATCH /lot-presentations/workspace/items/:unitId` body `{ comment: string | null }` - сохранить или очистить комментарий.

Изменить endpoints подборок:

- `POST /lot-presentations/collections/:collectionId/items` продолжает добавлять лот и не трогает `В работе`;
- `PATCH /lot-presentations/collections/:collectionId/items/:unitId` body `{ comment: string | null }` - сохранить или очистить комментарий в item конкретной подборки;
- `DELETE /lot-presentations/collections/:collectionId/items/:unitId` удаляет лот только из подборки.

Shared-типы:

- добавить `LotPresentationWorkspaceItem`;
- добавить `LotPresentationWorkspaceResponse`;
- добавить `UpdateLotPresentationItemCommentInput`;
- добавить `comment` в `LotPresentationCollectionItem`;
- оставить `LotPresentationLot.collectionIds`, чтобы UI мог показывать состояние добавления в подборки.

`POST /lot-presentations/documents` не меняет PDF-контракт: frontend передает `unitIds`. Для `В работе` `collectionId` не передается. Title для `Скачать все` во вкладке `В работе`: `В работе`. Title для одиночного PDF: текущий `getLotTitle(lot)`.

## Frontend Design

### Общая структура

Страница `/presentations` получает две вкладки:

- `В работе`;
- `Мои подборки`.

Визуальная плотность согласована через companion mockup: компактные плитки, до 5 лотов в ряд на широком экране. Карточки не должны быть крупными промо-блоками.

### Вкладка `В работе`

Верхняя зона:

- `Скачать все`;
- `Очистить всё`;
- `Добавить подборку`.

Основная зона:

- сетка лотов плитками;
- пустое состояние, если в работе нет лотов;
- предупреждение о незаполненных контактах брокера остается, потому что PDF без телефона и email не скачивается.

Плитка лота:

- планировка или fallback `Нет плана`;
- название лота;
- объект/ЖК;
- цена;
- площадь;
- этаж;
- статус;
- actions: скачать один PDF, добавить в подборку, удалить из `В работе`, комментарий;
- кнопка `Добавить комментарий` или `Изменить комментарий`.

Если комментарий есть, на плитке показывается активная иконка комментария. Клик открывает модалку просмотра/редактирования.

### Вкладка `Мои подборки`

Сохраняется боковая колонка подборок:

- список подборок;
- создание через `+` и текущую modal-flow;
- переименование и удаление подборки.

Правая рабочая зона выбранной подборки:

- лоты показываются такими же плитками;
- действия на плитке: скачать один PDF, удалить из подборки, комментарий подборки;
- добавление комментария меняет только item выбранной подборки;
- PDF по всей подборке и PDF по выбранным/одиночным лотам не включают комментарии.

### Добавление из объекта

`LotCollectionAction` заменяется новым workspace-действием для страницы объекта:

- из карточки лота `/objects/:slug/lots/:unitId` кнопка сразу добавляет лот в `В работе`;
- из таблицы лотов объекта иконка сразу добавляет лот в `В работе`;
- если лот уже в `В работе`, показывается added-state;
- клик по added-state ведет на `/presentations` во вкладку `В работе`.

Обязательная модалка выбора/создания подборки больше не появляется при добавлении из объекта.

### Добавление в подборку из `В работе`

Иконка `Добавить в подборку` на плитке открывает picker подборок:

- существующие подборки показываются списком;
- подборки, где лот уже есть, отмечаются и не дублируются;
- можно создать новую подборку и сразу добавить туда лот;
- после добавления лот остается в `В работе`.

## Error Handling

- Добавление недоступного лота возвращает текущую ошибку `Лот недоступен для презентации`.
- Повторное добавление в `В работе` не создает дубль и возвращает актуальное состояние.
- Комментарий длиннее 1000 символов отклоняется backend-валидацией; frontend также ограничивает ввод.
- Скачивание PDF с лотом без планировки сохраняет текущую ошибку генератора.
- Если контакты брокера не заполнены, кнопки скачивания disabled, а над рабочей зоной показывается текущее предупреждение о профиле. Backend-ошибка профиля остается защитой от race condition.

## Testing

Backend:

- Prisma/schema test на новую модель `LotPresentationWorkspaceItem` и поле `comment`;
- `GET /lot-presentations/workspace` возвращает только items текущего пользователя;
- `POST /workspace/items` добавляет лот, не дублирует при повторном добавлении и сохраняет порядок;
- `DELETE /workspace/items/:unitId` удаляет только item текущего пользователя;
- `DELETE /workspace/items` очищает только рабочую зону текущего пользователя;
- `PATCH /workspace/items/:unitId` сохраняет и очищает комментарий, отклоняет >1000 символов;
- `PATCH /collections/:collectionId/items/:unitId` сохраняет комментарий только в конкретной подборке;
- `createDocument` не включает комментарии и продолжает работать по `unitIds`.

Frontend:

- `/presentations` содержит вкладки `В работе` и `Мои подборки`;
- `В работе` рендерит плиточную сетку и не требует выбранной подборки;
- плитка содержит actions: скачать, добавить в подборку, удалить, комментарий;
- `Мои подборки` сохраняет боковую колонку и рендерит лоты плитками;
- добавление из объекта вызывает workspace endpoint, а не collection picker;
- active-state отображается для лота, который уже в `В работе`;
- комментарий создает активную иконку и открывается в модалке;
- `Очистить всё` вызывает workspace clear и не трогает подборки.

Manual QA:

- открыть `/objects/:slug`, добавить лот в работу из карточки лота и из таблицы лотов;
- открыть `/presentations`, проверить вкладку `В работе`, плитки и порядок добавления;
- скачать один лот и все лоты в работе;
- добавить комментарий, закрыть/перезагрузить страницу и проверить сохранение;
- добавить лот из `В работе` в подборку и убедиться, что он остался в работе;
- открыть `Мои подборки`, выбрать подборку в боковой колонке, проверить плитки и отдельный комментарий;
- очистить `В работе` и проверить, что подборки и история PDF остались.

## Scope Boundaries

- PDF-шаблон и visual layout самого PDF не меняются.
- Комментарии не выводятся в PDF.
- Drag-and-drop и ручная сортировка не добавляются.
- Права/roles/seed не меняются.
- Новые UI-библиотеки и зависимости не добавляются.
